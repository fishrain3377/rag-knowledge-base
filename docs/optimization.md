# 检索与性能优化指南

本文档列出从「基线可用」到「生产级」的优化路径，按投入产出比排序。

## 1. 检索质量优化

### 1.1 切分策略调参
| 参数 | 当前默认 | 说明 | 调优方向 |
|---|---|---|---|
| `chunk_size` | 500 | 单块字符数 | 知识密集型文档（论文/合同）可降至 300–400；科普类可升到 600–800 |
| `chunk_overlap` | 50 | 相邻块重叠 | 增大到 10–20% 的 chunk_size 可减少切分断句导致的召回丢失 |

**验证方法**：对典型问题集统计 Hit@k，观察提升来自切分还是模型。

### 1.2 混合检索（BM25 + 向量）
向量检索对语义相似有效，但对**精确词匹配**（型号、编号、人名）可能漏检。
建议引入 BM25 稀疏检索做加权融合：

```
final_score = α * 向量相似度 + (1 - α) * BM25 得分
```

推荐实现：`rank_bm25`（纯 Python，无重依赖）或 `elasticsearch`（量大时）。

### 1.3 Rerank 重排
召回 top_k（如 20）后，用交叉编码器精排取前 5，可显著提升答案质量：

```python
from sentence_transformers import CrossEncoder
reranker = CrossEncoder("BAAI/bge-reranker-base")
scores = reranker.predict([[query, doc] for doc in candidates])
```

成本：一次 rerank 约 n 次交叉编码推理，适合问答量不大、对质量敏感的场景。

### 1.4 查询改写
用户问题口语化时，先用 LLM 将问题改写为检索友好的表述（补充实体、去指代），
再做向量化。成本增加一次 LLM 调用，收益在长对话场景明显。

### 1.5 元数据过滤
为文档打标签（部门/日期/类型），检索时按标签过滤，缩小候选集、提升精度。
可在 `Document.metadata` 中扩展字段，`FaissStore` 增加过滤条件。

## 2. 性能优化

### 2.1 向量检索
| 规模 | 方案 | 说明 |
|---|---|---|
| < 100 万 | `IndexFlatIP`（当前） | 暴力检索，精确度最高，内存随规模线性增长 |
| 100 万+ | `IndexIVFFlat` | 聚类倒排，速度×10 量级，精度轻微下降 |
| 海量/内存受限 | `IndexIVFPQ` / `IndexHNSW` | 量化压缩，召回有损，需按业务验收 |

`faiss.index_factory` 可一行切换：`"IVF100,Flat"`、`"HNSW32"` 等。

### 2.2 Embedding 服务化
- 小模型（bge-small）CPU 即可；**bge-large / m3e-large 建议 GPU**；
- 多次启动重复加载模型耗时，可把 embedding 部署为独立服务（如 `text-embeddings-inference`），
  API 服务通过 HTTP 调用，支持并发批处理。

### 2.3 缓存
- **查询缓存**：相同/相似问题命中缓存（`redis` 或内存 LRU），QPS 场景收益大；
- **文档级缓存**：上传过的文档按内容哈希跳过重复向量化。

### 2.4 LLM 链路
- 并发控制：FastAPI 侧用 `asyncio.Semaphore` 限制并发 LLM 请求，避免打爆限流；
- 流式输出：`/ask` 支持 SSE 流式返回，首字延迟显著下降（体验优化）；
- 小模型提速：对简单问题走小模型、复杂问题走大模型的路由策略。

## 3. 可观测与评测

### 3.1 评测指标（见 `experiments/result.md`）
- **Hit@k / Recall@k**：标准答案所在文档块是否进入召回前 k；
- **MRR**：首个命中位置的倒数均值；
- **端到端人工评分**：答案正确性 + 引用准确性（引用是否真的支撑了回答）。

### 3.2 日志与监控
- 记录每次问答的：问题、top_k 得分分布、检索耗时、LLM 耗时、有无引用；
- 抽样人工标注「检索失败 / 生成幻觉」两类失败，反推优化优先级。

## 4. 安全与合规
- 私有知识库建议内网部署，`OPENAI_API_KEY` 只经环境变量注入，不入库不进日志；
- 若数据不可出域，LLM 也应切换为本地部署模型（如 Qwen 系列，兼容 OpenAI 协议）；
- 上传文件做大小与类型白名单校验（当前 API 已做扩展名白名单）。
